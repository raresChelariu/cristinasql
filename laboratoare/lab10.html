Variabile în psql

Variabilele au rolul de a suplini constante, condiții utilizate în clauza WHERE, nume de câmpuri utilizate în clauza ORDER BY, nume de tabele sau chiar întregi fraze SELECT, pentru a refolosi aceeași interogare cu valori diferite.

În consola psql variabilele se definesc cu meta-comanda \set și se folosesc prefixându-le cu :. Pentru a insera valoarea ca șir de caractere (între apostroafe) se folosește forma :'nume'.

Exemplu 1:

\set an 1
\set nume 'P%'
SELECT * FROM studenti
    WHERE an = :an AND nume LIKE :'nume';

Exemplu 2:

\set camp_afisare prenume
\set camp_sortare prenume
SELECT nume, :camp_afisare
    FROM studenti
    ORDER BY :camp_sortare;

Valoarea poate fi cerută interactiv de la utilizator cu \prompt:

\prompt 'Anul: ' an
SELECT * FROM studenti WHERE an = :an;

Variabila este stocată pe parcursul sesiunii psql până la eliminarea ei cu comanda \unset sau până la închiderea sesiunii.

\unset camp

Comenzile \set, \unset și \prompt sunt specifice utilitarului psql și nu fac parte din limbajul SQL. În pgAdmin (Query Tool) acestea nu sunt disponibile - acolo scrieți direct interogarea cu valorile concrete dorite.

Secvențe

De multe ori suntem puși în situația de a crea atribute sintetice care să joace rol de cheie, deci să ia valori unice în cadrul unei tabele. Secvențele sunt obiecte care ne ajută să generăm automat numere întregi unice în momentul inserării înregistrilor.

Sintaxa creării unei secvențe:

CREATE SEQUENCE nume_secventa
  [INCREMENT BY n]                 -- pasul
  [START WITH n1]                  -- valoarea de start
  [MAXVALUE n_max | NO MAXVALUE]   -- valoarea maxima
  [MINVALUE n_min | NO MINVALUE]   -- valoarea minima (pasul poate fi negativ -> sir descrescator)
  [CYCLE | NO CYCLE]               -- daca se continua generarea cand se ajunge la min/max

Funcția nextval('nume_secventa') generează următorul număr din șir, iar currval('nume_secventa') obține valoarea curentă (ultima generată în sesiune). nextval trebuie executată cel puțin o dată înainte de a putea folosi currval.

Exemplu:

CREATE SEQUENCE s1
  INCREMENT BY 2
  START WITH 10
  MAXVALUE 15;

SELECT nextval('s1'); --executati in mod repetat comanda; cand ridica eroare?

Pentru a elimina secventa se va executa comanda 

DROP SEQUENCE nume_secventa;

În PostgreSQL, modul idiomatic de a avea o cheie cu auto-incrementare este folosirea tipului SERIAL sau a clauzei GENERATED ALWAYS AS IDENTITY la crearea tabelei, care creează și gestionează automat o secvență:

CREATE TABLE exemplu (
  id INTEGER GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  descriere VARCHAR(40)
);

Comenzi DDL - creare/modificare structuri de date

Aceste comenzi sunt menite a crea sau a șterge tabele (sau alte tipuri de obiecte), precum și a modifica structura tabelelor (obiectelor) existente. Comenzile necesare fac parte din componenta DDL (Data Definition Language) a limbajului SQL.

CREATE TABLE AS

Comenzile de creare a tabelelor au fost pe larg explicate la curs, cu diversele constrângeri care pot fi impuse asupra datelor la momentul creării. Aici tratăm doar comanda CREATE cu subinterogări.

CREATE TABLE nume_tabel [(col1, col2,...)] AS fraza_select;

Comanda este similară cu cea dedicată creării viewului, diferența fiind că la crearea unui tabel, acesta este umplut cu datele returnate de interogare.

Exercitii

Asigurați-vă că lucrați pe datele inițiale (re-rulați scriptul de creare dacă ați modificat datele). Creați apoi o tabelă care să stocheze numele, prenumele, bursa și mediile studenților.

ALTER TABLE

Structura tabelelor create deja poate fi modificată, chiar dacă tabelul conține deja date. Modificările pot să vizeze adăugarea de noi coloane, ștergerea unor coloane existente, modificarea definiției unei coloane (tipul și constrângerile impuse), redenumirea unei coloane, redenumirea tabelului, adăugarea sau ștergerea de constângeri (chei candidat, chei primare, chei străine, constrângeri NOT NULL, CHECK).

Găsiți în continuare comenzile necesare:

Pentru adăugarea unor coloane într-un tabel:

ALTER TABLE nume_tabel ADD COLUMN col1 definitie_col1 [, ADD COLUMN col2 definitie_col2 ...]
Exemplu: 
ALTER TABLE cursuri ADD COLUMN abreviere CHAR(2),
                    ADD COLUMN descriere VARCHAR(40) DEFAULT 'curs obligatoriu';

Pentru eliminearea unor coloane dintr-un tabel:

 
ALTER TABLE nume_tabel DROP COLUMN col
ALTER TABLE cursuri DROP COLUMN descriere;

Pentru modificarea tipului unei coloane:


  ALTER TABLE nume_tabel ALTER COLUMN col1 TYPE definitie_col1 [, ALTER COLUMN col2 TYPE definitie_col2 ...]
ALTER TABLE profesori ALTER COLUMN nume TYPE VARCHAR(20),
                      ALTER COLUMN prenume TYPE VARCHAR(20);

Pentru a impune sau a elimina constrângerea NOT NULL pe o coloană:

ALTER TABLE studenti ALTER COLUMN nume SET NOT NULL;
ALTER TABLE studenti ALTER COLUMN nume DROP NOT NULL;

Pentru redenumirea unor coloane:


ALTER TABLE nume_tabel RENAME COLUMN col_veche TO col_noua
ALTER TABLE note RENAME COLUMN valoare TO nota;

Pentru redenumirea tabelului:


ALTER TABLE nume_vechi_tabel RENAME TO nume_nou_tabel
ALTER TABLE profesori RENAME TO cadre_didactice;

Pentru adăugarea unor constrangeri asupra unei coloane dintr-un tabel (PRIMARY KEY, FOREIGN KEY, CHECK(conditie), UNIQUE(coloana)):

ALTER TABLE nume_tabel ADD CONSTRAINT nume_constrangere definitie_constrangere;
ALTER TABLE studenti ADD CONSTRAINT 
     pk_studs PRIMARY KEY (nr_matricol);
ALTER TABLE note ADD CONSTRAINT 
     fk_studs FOREIGN KEY (nr_matricol) 
     REFERENCES studenti(nr_matricol) ON DELETE CASCADE;

Pentru eliminarea unor constrangeri definite de utilizator:

     
ALTER TABLE nume_tabel DROP CONSTRAINT nume_constrangere;
ALTER TABLE note DROP CONSTRAINT fk_studs;

Tranzacții

O tranzacție reprezintă un grup de comenzi de modificare de date (DML) care trebuie executate împreună, pentru a garanta consistența datelor. Eșuarea oricărei comenzi din cadrul unei tranzacții determină revenirea la starea inițială, dinaintea tranzacției.

Implicit, PostgreSQL funcționează în mod autocommit: fiecare comandă reprezintă propria sa tranzacție și este salvată (commit) automat imediat ce se execută cu succes. Pentru a grupa mai multe comenzi într-o singură tranzacție, o începem explicit cu comanda BEGIN (sau START TRANSACTION) și o încheiem cu COMMIT sau ROLLBACK.

Comanda COMMIT face permanente toate modificările efectuate de la începutul tranzacției. Comanda ROLLBACK încheie tranzacția readucând baza de date la starea de dinaintea începerii ei. O eroare în cadrul tranzacției sau o cădere a sistemului are același efect ca un ROLLBACK - este modalitatea prin care este protejată integritatea datelor.

În PostgreSQL și comenzile DDL (CREATE, ALTER, DROP) sunt tranzacționale: dacă au fost executate în interiorul unei tranzacții deschise cu BEGIN, ele pot fi anulate cu ROLLBACK, la fel ca modificările de date. Astfel, dacă într-o tranzacție ștergeți date și apoi creați un tabel, un ROLLBACK anulează ambele operații.

Pe parcursul unei tranzacții pot fi adăugați niște marcatori/indicatori cu ajutorul cărora să putem reveni la stări intermediare. Adăugarea unui indicator se realizează cu ajutorul comenzii SAVEPOINT nume_indicator iar revenirea la starea bazei de date din acel moment se realizează cu ajutorul comenzii ROLLBACK TO SAVEPOINT nume_indicator.
